# 커밋구조대 (Commit Rescue)

> Git을 **원고**에 비유해 그림으로 보여주고, 문제가 생겼을 때 필요한 명령어와
> **그 명령이 바꾸는 칸**을 함께 알려주는 서비스.
> 설명에서 끝내지 않고 **같은 상황의 실습실로 이어집니다**(§13).

## 1. 무엇을 해결하나

Git 입문자의 어려움은 "명령어를 모르는 것"이 아니라
**"내 상황에 어떤 명령어를 써야 하는지, 그리고 그 명령이 무엇을 바꾸는지 모르는 것"** 입니다.

- 검색어를 만들 수 없다 — "커밋을 잘못했어요"를 어떤 용어로 검색해야 하는지 모른다
- 검색 결과가 대부분 옛날 명령어(`checkout`, `reset`) 기준이라 지금 권장되는 `switch` / `restore`와 연결되지 않는다
- 명령어를 실행했는데 **내 컴퓨터가 바뀐 것인지, GitHub이 바뀐 것인지** 구분하지 못한다
- 되돌릴 수 없는 명령을 실행해 작업을 잃는다 — 무엇을 잃게 되는지 미리 알 방법이 없다

이 서비스는 상황을 평소 쓰는 말로 입력하면 ① 무슨 일인지 한 줄 정리 ② **확인된 사실과 추정 구분**
③ 단계별 명령어 ④ **각 명령이 바꾸는 영역과 바꾸지 않는 영역** ⑤ 위험하면 **잃게 되는 것 먼저 확인**을 보여줍니다.

## 2. 핵심 모델 — 5칸과 하나의 경계

이 서비스는 Git을 **원고**에 비유합니다. 쉬운 말을 앞에 두고 원래 용어를 나란히 적습니다 —
검색할 때는 원래 용어가 필요하기 때문입니다.

| 쉬운 말 | 원래 용어 |
|---|---|
| 책상 | 작업 폴더 working directory |
| 버전 하나 | 커밋 commit |
| 이번 버전에 넣을 것 고르기 | 스테이징 staging · index |
| 내 기록함 | 로컬 저장소 `.git` |
| 작업본 | 브랜치 branch |
| 지금 보고 있는 곳 | HEAD |
| 공유 폴더 | 원격 저장소 remote · GitHub |
| **공유 폴더 메모** | **`origin/main`** |

사전 아래에는 Git(내 컴퓨터의 프로그램)과 GitHub(인터넷 서비스)의 차이를 따로 설명합니다.
둘을 같은 것으로 아는 데서 오는 혼란이 잦기 때문입니다.

비유는 “어디에 무엇이 담기는지”를 잡는 데까지만 씁니다. Git이 실제로는 파일 전체를 매번 복사하지 않는다는 것은
처음 배울 때 몰라도 되고, 익숙해지면 원래 용어만 쓰게 됩니다.

### 5칸 모델

```
┌─ 내 컴퓨터 (로컬) ────────────────────────┐
│   ① 작업 폴더                              │
│        ↕                                   │
│   ② 스테이징 영역 (index)                   │
│        ↕                                   │
│   로컬 저장소 (.git)                        │
│        ├── ③ main         내 커밋 기록       │
│        └── ④ origin/main  마지막 fetch에서   │
│                           본 GitHub의 상태   │
└────────────────┬──────────────────────────┘
                 ↕ 네트워크
   ⑤ GitHub의 main   ← 실제 원격 상태
```

**`origin/main`은 GitHub에 있는 것이 아니라 내 컴퓨터에 있습니다.** 마지막으로 `fetch`했을 때 본
GitHub 상태를 적어둔 메모입니다. 동료가 push해도, 내가 `fetch`하기 전까지 `origin/main`은 움직이지 않습니다.
초보자가 `fetch`와 `pull`을 구분하지 못하는 근본 원인이 여기에 있어서, 4영역이 아니라 5영역으로 그립니다.

## 5. 실행 방법

### 로컬 (프론트만 보기)

`api/`를 쓰지 않는 화면(개념, 정적 카드 8종, 명령어 사전, **실습실 전체**)은
정적 서버만으로 전부 동작합니다. 실습실은 네트워크로 나가지 않으므로 여기서 모든 기능을 볼 수 있습니다.

```bash
python3 -m http.server 3000
```

### 테스트

```bash
node --test tests/*.test.js
```

의존성이 없습니다. `package.json`도 필요 없습니다 — node 내장 test runner 와 CommonJS 로만 돌립니다.
상태 엔진이 DOM 을 모르게 만든 이유가 이것입니다.

### 로컬 (AI 기능 포함)

```bash
npm i -g vercel
echo "GEMINI_API_KEY=발급받은_키" > .env    # .env 는 .gitignore 에 있습니다
vercel dev
```

### 배포

```bash
vercel --prod
```

배포 환경에서는 `.env`가 존재하지 않습니다. **Vercel → Settings → Environment Variables**에
`GEMINI_API_KEY`를 따로 등록해야 합니다.

## 6. 환경 변수

| 이름 | 필수 | 설명 |
|---|:---:|---|
| `GEMINI_API_KEY` | O | Google AI Studio에서 발급받은 키. 서버리스 함수 안에서만 `os.environ`으로 읽습니다 |
| `GEMINI_MODEL` | X | 사용할 모델. 기본값 `gemini-3.5-flash-lite`. 모델이 은퇴하면 404가 나므로, 그때는 이 변수로 교체합니다 |

키는 프론트엔드 코드나 네트워크 응답에 절대 포함되지 않습니다.
서버 로그에 상류 오류를 남길 때도 본문에서 키 문자열을 `***`로 가린 뒤 출력합니다.

**유출이 의심되면 먼저 AI Studio에서 폐기·재발급하고, 그다음 커밋 이력을 정리하세요.**
순서를 바꾸면 정리하는 동안에도 키가 유효합니다.

### 키 굳히기 (Google Cloud Console)

| 설정 | 위치 | 값 |
|---|---|---|
| **API 제한** | Credentials → 해당 키 → API restrictions | `Generative Language API` **하나만** |
| **하루 요청 상한** | IAM & Admin → Quotas → `Generative Language API` | 기본값보다 낮게 |

- **Application restrictions는 `None`으로 둡니다.** HTTP referrer 제한은 브라우저 요청용이라
  서버에서 부르는 이 키에는 걸면 전부 막힙니다. IP 제한도 Vercel 서버리스 IP가 고정이 아니라 쓸 수 없습니다
- 결제를 붙였다면 예산 알림(Billing → Budgets)도 걸어두되, **알림은 끊어주지 않습니다.**
  실제로 멈추는 것은 위의 할당량 상한입니다
- **`GEMINI_API_KEY`는 Production 환경에만 등록하세요.** Preview에도 있으면
  브랜치 배포 URL을 아는 사람이 그쪽으로 키를 쓸 수 있습니다

## 7. API 명세

### `POST /api/rescue`

**요청**

```json
{
  "situation": "커밋했는데 파일 하나를 빼먹었어요",
  "executedCommand": "git commit -m \"기능 추가\"",
  "errorMessage": "",
  "statusOutput": "",
  "alreadyPushed": "unknown",
  "level": "beginner"
}
```

| 필드 | 타입 | 필수 | 제한 |
|---|---|:---:|---|
| `situation` | string | O | 5~1,000자 |
| `executedCommand` | string | X | 300자 |
| `errorMessage` | string | X | 1,000자 |
| `statusOutput` | string | X | 1,000자 |
| `alreadyPushed` | enum | X | `yes` / `no` / `unknown` (기본) |
| `level` | enum | X | `beginner` (기본) / `intermediate` |

**응답 200**

```json
{
  "관련없음": false,
  "상황요약": "마지막 커밋에 포함되어야 할 파일이 빠진 상태로 보입니다.",
  "근거구분": {
    "확인됨": ["커밋을 이미 실행했다"],
    "추정": ["아직 push하지 않았을 것으로 보인다"],
    "추가확인": ["git status 결과"]
  },
  "위험도": "주의",
  "오류위치": "local",
  "명령어": [
    { "cmd": "git status", "설명": "...", "변경영역": [], "유지영역": ["work", "staging", "local", "origin-tracking", "remote"] }
  ],
  "주의사항": ["..."],
  "그래프템플릿": "amend-add-file"
}
```

**오류 응답**

| 상태 | 코드 | 언제 |
|---|---|---|
| 400 | `INVALID_INPUT` | 길이·형식 위반, 비밀키 패턴 탐지 |
| 403 | `FORBIDDEN` | `Origin`이 없거나 `Host`와 다름 (우리 화면에서 온 요청이 아님) |
| 403 | — | Vercel 방화벽이 CDN 단에서 차단 (본문은 Vercel 형식) |
| 429 | `RATE_LIMITED` | 상류 한도 초과 (`retryAfter` 포함) |
| 500 | `SERVER_ERROR` | 키 미설정 등 서버 설정 문제 |
| 502 | `UPSTREAM_ERROR` | Gemini 호출 실패 |
| 502 | `BAD_FORMAT` | 응답이 JSON이 아니거나 잘림 |
| 502 | `UNSAFE_COMMAND` | AI가 내놓은 명령이 셸 검증에 걸림 (§8 참고) |

서버는 Gemini의 오류 코드나 본문을 그대로 전달하지 않고 위 형태로 정규화합니다.
**내부 stack trace나 API 응답 원문을 노출하지 않습니다.**
응답의 `그래프템플릿` 값이 허용 목록에 없으면 서버가 `none`으로 치환합니다.

## 8. 안전 · 보안 설계

두 가지를 나눠 다룹니다. **안전**은 사용자가 자기 작업을 잃지 않게 하는 것이고,
**보안**은 이 서비스가 사용자를 해치거나 남에게 이용당하지 않게 하는 것입니다.

| 무엇을 | 어떻게 | 어디에 |
|---|---|---|
| 작업 손실 | 위험 명령 6단계 손실 점검 게이트 | `js/rescue.js` |
| 프롬프트 인젝션 | 명령어 셸 검증 — **서버 + 화면 2겹** | `api/rescue.py` · `js/rescue.js` |
| 남의 사이트·스크립트 호출 | `Origin` 확인 — **방화벽 + 서버 2겹** | Vercel Firewall · `api/rescue.py` |
| 할당량 소진 | 요청 제한(IP당 10회/600초), 정적 카드 8종은 API 미호출 | Vercel Firewall |
| XSS | 전 구간 이스케이프 + CSP(`unsafe-inline` 없음) | 전체 · `vercel.json` |
| 키 유출 | 서버에서만 읽기, 로그 마스킹, API 제한 | `api/rescue.py` · Cloud Console |
| 사용자 비밀키 실수 | 토큰 패턴 8종 전송 차단 (서버가 최종 관문) | `api/rescue.py` |

### 위험 명령 6단계 손실 점검 게이트

`위험도`가 `위험`인 결과는 아래를 모두 확인해야 명령어 복사가 열립니다.

| 단계 | 내용 |
|---|---|
| 1 | `git status`로 현재 상태 확인 |
| 2 | `git diff` / `git diff --staged`로 무엇을 잃게 되는지 확인 |
| 3 | 미커밋 변경이 있다면 `git stash push -u`로 먼저 대피 |
| 4 | 커밋 기록 보호가 필요하면 백업 브랜치 |
| 5 | **예상 손실 목록 확인** |
| 6 | 위험 명령 복사 (여기서 활성화) |

**백업 브랜치만으로는 부족합니다.** `git branch backup-...`은 이미 커밋된 기록만 보호하며,
작업 폴더의 미커밋 변경과 스테이징 내용은 지켜주지 못합니다. 3단계가 존재하는 이유입니다.

다만 **잠금을 우회할 수단은 남겨둡니다.** 명령어 텍스트는 항상 드래그로 선택할 수 있고,
"확인했습니다, 그냥 진행" 링크가 작게 배치되어 있습니다. 사용자의 판단을 완전히 막는 것이 목적은 아닙니다.

### reflog 안내 범위

> `git reflog`는 **이동하거나 삭제된 커밋**을 찾는 데 유용합니다.
> 다만 **한 번도 커밋하지 않은 파일 변경까지 복구해주지는 않습니다.**
> 그래서 위험한 명령 전에 먼저 커밋하거나 stash해두는 것이 중요합니다.

### 프롬프트 인젝션 — 명령어 셸 검증

**이 서비스가 사용자에게 시키는 유일한 행동이 "복사해서 터미널에 붙여넣기"입니다.**
그래서 사람이 실행할 문자열이 가장 엄격해야 합니다.

입력 네 칸(상황·실행한 명령·오류 메시지·`status` 결과)은 그대로 프롬프트로 들어갑니다.
인젝션 문구가 섞인 텍스트를 건네받은 사용자가 그걸 붙여넣으면, 모델이 엉뚱한 명령을
첫 단계로 내놓을 수 있습니다. 화면에는 얌전한 `<code>`로 보이고 복사 버튼이 그대로 작동합니다.

**위험 게이트는 이걸 막지 못합니다.** 게이트를 여는 `위험도`를 정하는 것도 같은 모델이라,
`안전`으로 내놓으면 6단계 점검 없이 복사가 열립니다.

`api/rescue.py`의 `assert_safe_command()`가 세 겹으로 봅니다.

| 검사 | 거르는 것 | 걸리는 예 |
|---|---|---|
| `git `로 시작하는가 | git 명령이 아닌 것 전부 | <code>curl … &#124; sh</code>, `bash -c …`, `sudo …` |
| 셸 특수문자가 있는가 | <code>;</code> <code>&#124;</code> <code>&amp;</code> <code>$</code> <code>&#96;</code> <code>&#92;</code> <code>&lt;</code> <code>&gt;</code> 개행 | <code>git status; curl … &#124; sh</code>, <code>git log &#96;whoami&#96;</code> |
| git 자체 실행 통로인가 | `--upload-pack`, `--receive-pack`, `--exec`, `core.pager`, `core.editor`, `sshCommand`, `alias.`, `filter.`, `difftool`, `mergetool`, 전역 `-c` | `git -c core.pager='sh -c id' log` |

- **자리 표시자는 먼저 걷어냅니다.** `git switch <브랜치>`는 꺾쇠를 정상적으로 쓰므로,
  `<...>` 쌍을 제거한 뒤 나머지에서만 꺾쇠를 금지합니다
- **전역 `-c`는 앞머리에서만 잡습니다.** `-c `를 단순 부분일치로 찾으면
  `git switch -c <브랜치>`(새 작업본 만들기)까지 막힙니다
- 하나라도 걸리면 **그 단계만 빼지 않고 응답 전체를 버립니다.**
  1번을 빼고 2·3번만 남기면 순서가 끊긴 계획이 되는데, 그게 더 위험합니다

**같은 검사를 화면에서도 합니다**(`js/rescue.js`의 `isSafeCommand`).
같은 질문을 다시 하면 `sessionStorage`에 저장해둔 답을 그대로 다시 그리는데,
이 경로는 서버를 타지 않으므로 서버 검증도 타지 않기 때문입니다.
걸린 단계는 복사 버튼을 주지 않고, **무엇이 왜 빠졌는지는 그대로 보여줍니다.**
조용히 빼면 사용자는 순서가 비어 있는 줄 모르고 실행합니다.

> 검증: 정상 명령 49개 오탐 0 / 공격 22개 차단 22.
> 배포본에서 `sessionStorage`를 실제로 오염시켜 확인 — 5단계 중 정상 1개만 복사 가능.

### 요청 출처 확인

브라우저는 GET/HEAD가 아닌 요청에 `Origin` 헤더를 **반드시** 붙입니다(같은 출처여도).
`curl`은 일부러 넣지 않는 한 없습니다. 그래서 `Origin`이 없거나 `Host`와 다르면
우리 화면에서 온 요청이 아니므로 `403`으로 끊습니다.

- 도메인을 코드에 박지 않고 **`Host` 헤더와 대조**합니다 — 프로덕션·프리뷰·커스텀 도메인이 자동으로 맞습니다
- **Gemini를 부르기 전에** 끊으므로 할당량을 태우지 않습니다
- 헤더 위조로 우회는 됩니다. 정교한 공격을 막는 장치가 아니라,
  **아무 생각 없이 도는 스크립트가 하루치를 태우는 것**을 막는 장치입니다

같은 조건이 Vercel 방화벽에도 걸려 있어 대부분은 CDN 단에서 끊깁니다(`x-vercel-mitigated: deny`).
서버 검사는 그 규칙이 사라졌을 때의 백업입니다.

### 브라우저 보안 헤더

`vercel.json`에서 모든 응답에 붙입니다.

| 헤더 | 값 |
|---|---|
| `Content-Security-Policy` | `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains; preload` |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `DENY` |
| `Referrer-Policy` | `no-referrer` |
| `Permissions-Policy` | 위치·마이크·카메라·결제·USB 전부 차단 |

**`script-src`에 `'unsafe-inline'`이 없습니다.** 이걸 넣으면 CSP가 XSS를 막는 기능이
통째로 꺼집니다(공격자가 심는 것도 인라인이므로). 그래서 `<head>`의 테마 인라인 스크립트를
`js/theme.js`로 뺐습니다. `defer` 없이 부르는 것은 그대로입니다 —
첫 페인트보다 늦으면 다크 모드에서 흰 화면이 번쩍입니다.

CSP는 **넣자마자 실제 버그를 하나 잡았습니다.** 결과 화면의 그래프 영역이
`style="margin-top:22px"`로 여백을 주고 있었는데 `style-src 'self'`에 막혀 조용히 사라졌습니다.
클래스로 옮겼습니다.

### XSS

결과 화면 전체가 `innerHTML`로 그려집니다. **AI 값이 닿는 자리는 전부 `escapeHtml`을 거칩니다**
— `data-copy` 같은 속성 자리 포함. 전수 점검에서 확인한 것:

- `href` / `src` / `on*`로 값이 흘러드는 곳 **0건**
- `eval` · `new Function` · `document.write` **0건**
- 외부 링크 **0건**
- 정규식 ReDoS — 입력이 1,000자로 묶여 있어 최악도 선형~2차
- `GRAPH_TEMPLATE_IDS`가 `Object.keys` 기반이라 프로토타입 키가 섞이지 않음

점검 중 **`riskBadge`가 프로토타입 체인 조회 결과를 이스케이프 없이 HTML에 넣고 있었습니다.**
`RISK_CLASS['constructor']`는 `undefined`가 아니라 `Object` 생성자를 돌려주고,
그게 `class` 속성과 본문에 그대로 붙습니다. 서버가 `위험도`를 세 값으로 정규화해서
지금은 닿지 않지만, 이스케이프 없는 자리는 조건 하나만 바뀌면 구멍입니다.
`hasOwnProperty`로 막았습니다.

- 토큰 형태 패턴은 **전송 전 차단** — 프론트와 서버 양쪽에서 검사

### 요청 한도 대응

정적 카드 8종은 API를 호출하지 않습니다(가장 큰 절감).

**서버 쪽 제한은 Vercel 방화벽이 맡습니다.** 아래 쿨다운은 전부 브라우저 안의 장치라
`curl` 앞에서는 없는 것과 같습니다. 실제로 막는 것은 이쪽입니다.

| 규칙 | 설정 | 막는 것 |
|---|---|---|
| `rescue-api-origin` | `Origin` ≠ 우리 도메인 → Deny | 스크립트 대부분 (함수 호출 0) |
| `rescue-api-rate-10m` | 10회 / 600초 / Key: **IP Address** → Deny | `Origin`을 위조한 반복 호출 |

- **Key는 IP 하나만 씁니다.** Key는 카운터를 몇 개로 쪼갤지를 정하므로 **추가하면 더 느슨해집니다.**
  특히 User-Agent는 요청자가 헤더 한 줄로 바꾸는 값이라, Key에 넣는 순간 제한이 무력화됩니다
- **창은 600초입니다**(무료 플랜 최댓값). 60초로 두면 순간 폭주만 막고 하루 총량은
  전혀 안 묶입니다 — IP 하나가 하루 14,400회를 태울 수 있습니다. 600초 창은 1,440회로 묶습니다
- 무료 플랜은 rate limit 규칙을 **하나만** 걸 수 있습니다. 그래서 `Origin` 차단(Deny 액션)이
  실질적인 첫 번째 방어선이고, rate limit은 그걸 위조한 경우를 위한 것입니다
- 방화벽은 **`403`으로 끊습니다.** 클라이언트는 `403`을 재시도하지 않습니다 —
  재시도하면 한 번 막힐 때마다 1→2→4초로 네 번을 두드려 스스로 차단을 연장합니다.
  `Fixed Window`라 언제 풀릴지는 창의 어디에서 걸렸느냐에 달려 있어
  **특정 시각을 약속하지 않고** "최대 10분까지 막힐 수 있다"로 안내합니다

**브라우저 쪽 절감 장치** — 우회 가능하지만, 정상 사용자의 불필요한 호출을 줄입니다.

- **전송 후 10초 쿨다운.** 전송 버튼과 결과 화면의 "다시 시도" 버튼이 **같은 쿨다운을 공유**하고,
  남은 초가 두 버튼에 함께 표시됩니다. 한쪽에만 걸어두면 다른 쪽으로 그대로 우회됩니다
- `429` 응답은 서버가 알려준 `retryAfter`(기본 30초)만큼 실제로 잠급니다 — 안내 문구와 버튼 상태가 일치합니다
- 동일 입력은 `sessionStorage` 캐시로 재호출하지 않음
- 실패 시 1→2→4초 간격 재시도(최대 3회). 단 **재시도 전체에 20초 상한**이 있어,
  매 시도가 타임아웃을 꽉 채우더라도 사용자가 약속된 시간보다 오래 기다리지 않습니다
- 입력 길이 제한, 구조화된 출력으로 파싱 실패 재호출 방지

## 9. AI가 지키는 규칙

1. **첫 단계는 항상 `git status`** — 사용자가 상황을 잘못 설명했을 가능성을 이 단계가 걸러줍니다
2. `checkout`이 아니라 **`switch` / `restore`** 를 제시
3. 기본 브랜치는 `main`으로 가정
4. **이미 원격에 올라간 커밋은 `revert`** — push 여부가 `unknown`이면 확인 방법을 먼저 안내하고, 확정 전에는 되돌릴 수 없는 명령을 제안하지 않음
5. 각 명령마다 **변경 영역과 유지 영역을 모두 명시**
6. **확인된 사실과 추정을 구분** — 입력되지 않은 정보를 확정으로 서술하지 않음
7. **커밋 ID나 그래프를 직접 만들지 않음** — 검증된 템플릿 목록에서 고르고, 맞는 것이 없으면 `none`

### AI가 그래프를 만들지 않는 이유

AI는 사용자의 저장소를 볼 수 없습니다. 생성된 커밋 ID와 그래프는 실제 상태가 아니라 창작이고,
사용자는 그것을 자기 저장소로 오해합니다. **텍스트 오류보다 그림 오류가 더 강하게 각인됩니다.**
그래서 AI는 검증된 9종 중 하나를 고르기만 하고, 렌더링은 프론트엔드가 검수된 데이터로 수행합니다.
표시할 때는 항상 "이 그림은 개념 예시입니다. 현재 저장소의 실제 그래프가 아닙니다."를 함께 보여줍니다.

**Oh Shit, Git!?!** 은 목적이 가장 가깝습니다. "문제를 고치려면 그 문제의 이름을 이미 알아야 검색이 된다"는
인식에서 출발했지만, 목록에 없는 상황은 대응하지 못합니다.
**GitFluence** 는 메커니즘이 가장 가깝지만 명령어만 주고 결과 설명이 없습니다.
**시각화 도구군**은 모두 사용자가 명령어를 이미 안다는 전제에서 출발하고,
커밋 그래프가 중심이라 **작업 폴더·스테이징·`origin/main` 메모**는 상대적으로 약합니다.

**자연어 입력과 시각화를 결합한 서비스는 없습니다.** 명령어를 아는 사람에게는 시각화 도구가 있고,
모르는 사람에게는 명령어 생성기가 있지만, 모르는 사람에게 결과를 보여주는 것은 비어 있습니다.

**"내 오류에서 그 상황의 실습으로" 이어지는 것도 없습니다.** 시뮬레이터는 처음부터 쳐야 하고,
명령어 생성기는 실습이 없습니다. 이 서비스는 AI 결과 카드에서 같은 상태의 실습실로 바로 넘어갑니다(§13).

> 첫 화면의 핵심 행동을 방해하고, 경쟁 서비스로 사용자를 직접 이탈시키며, 표가 빠르게 낡기 때문입니다.

- cherry-pick, submodule, reflog 등은 아직 대상 범위 밖입니다 (실습실이 모르는 명령은 모른다고 답합니다)
- 무료 등급 API를 쓰므로 한도 초과 시 잠시 이용이 제한될 수 있습니다
- 명령을 대신 실행해주지 않습니다. 실행 판단과 책임은 사용자에게 있습니다

**그림에 대해 — 두 가지를 구분합니다**

| 어디 | 무엇 | 화면 표기 |
|---|---|---|
| 개념 설명 · AI 결과 카드 | 검수된 템플릿 9종 중 하나 | "이 그림은 **개념 예시**입니다" |
| 실습실 | 방금 친 명령이 만든 **그 실습실 안의 실제 상태** | 실제 상태라고 적습니다 |

실습실 그래프까지 "개념 예시"라고 적으면 사실과 다릅니다. 반대로 실습실이
여러분의 저장소를 읽어온 것처럼 보여도 안 됩니다. 그래서 두 문구를 나눠 씁니다.

## 12. 접근성

- **용어를 쉬운 말로 바꾸고 원래 용어를 병기**합니다. 커밋·브랜치가 무엇인지 모르는 사람도 읽을 수 있어야 하기 때문입니다
- **명령어 옵션은 짧은 형태(`-m`)와 긴 형태(`--message`)를 함께** 적습니다. 검색하면 둘 다 나오는데 같은 것인 줄 모르면 헷갈립니다
- **한 덩어리가 화면 높이를 넘지 않게** 맞췄습니다. 긴 설명·옵션·예시는 접어두고 필요할 때 펼칩니다
- 모든 폼 요소에 `label` 연결, 결과 영역에 `aria-live="polite"`
- **키보드만으로 네비게이션 · 입력 · 실행 · 결과 확인 가능**, `:focus-visible` 제거하지 않음
- 명령어 사전 카드는 카드 전체를 버튼으로 만들지 않고 **"영향 영역 보기" 전용 버튼**을 둡니다.
  카드에 `role="button"`을 주면 안에 있는 복사 버튼과 중첩되어 ARIA 위반이 되고,
  버튼의 접근가능한 이름이 카드 본문 전체(90자 넘는 문장)가 되어 스크린리더에서 쓸 수 없습니다
- **색 외에 선 종류 · 아이콘 · 텍스트로도 상태를 구분** — `origin/main`은 점선, 위험도 배지는 아이콘+텍스트 병기,
  영역 표시는 ▲ / = / · 기호 병기 (흑백 출력에서도 판독 가능)
- SVG에 `role="img"`과 `<title>` / `<desc>` 제공
- **실습실 그래프의 대체 텍스트는 "그래프가 있습니다"가 아니라 이름표 위치를 그대로 적습니다** —
  `main은(는) 1b9753c, origin/main은(는) 263fa6a (마지막 fetch 때 적어둔 메모)`.
  그림을 못 보는 사람에게 필요한 것이 그것이기 때문입니다. 같은 정보를 `git log --oneline --all`로도 볼 수 있습니다
- 실습실 터미널 기록은 `role="log"` + `aria-live="polite"` — 명령 결과가 읽힙니다
- `prefers-reduced-motion` 존중, `prefers-color-scheme` 기반 다크 모드 + 수동 토글

## 13. Git 실습실 (`lab.html`)

읽어서 안 믿기는 것이 하나 있습니다.

> `origin/main`은 GitHub에 있는 것이 아니라 **내 컴퓨터에** 있습니다.

이건 **동료가 push했는데 내 화면이 안 움직이는 것을 직접 봐야** 믿깁니다.
그래서 명령을 직접 쳐보는 실습실을 만들었습니다.

### 이 실습실을 만든 방식이 곧 주장입니다

오브젝트 저장소를 **둘로 나눴습니다.**

```js
state.objects          // 내 컴퓨터의 .git
state.github.objects   // GitHub 서버
state.remoteTracking['origin/main'].tip   // state.objects 만 가리킨다
```

`origin/main`이 로컬 저장소만 가리키게 하면, 다음이 **연출이 아니라 구조적으로 그럴 수밖에 없는 일**이 됩니다.

- 동료가 GitHub에 push해도 내 `origin/main`은 안 움직인다
- `git log`에 그 커밋이 안 보인다 (내 기록함에 없으니까)
- **`git fetch`를 해도 `git push`는 여전히 거절된다** — 받아온 것과 합친 것은 다르니까

마지막 줄이 이 서비스가 5칸으로 그리는 이유 전부입니다.
`fetch` 뒤에도 push가 막히는 것을 한 번 보면 `fetch`와 `pull`의 차이를 다시 헷갈리기 어렵습니다.

### 화면

```
┌─ 내 컴퓨터 ───────────────────────┐ ┊ ┌─ GitHub ─┐
│ 1.작업 폴더 │ 2.스테이징          │ ┊ │ 5.원격    │
│ 3~4. 내 기록함 (main · origin/main)│ ┊ │  main    │
└───────────────────────────────────┘ ┊ └──────────┘
                              네트워크 경계
┌─ 터미널 ──────────────────────────────────────────┐
│ $ git fetch                                       │
│ 출력 · 쉬운 말 설명 · 바뀐 칸 / 안 바뀐 칸          │
└───────────────────────────────────────────────────┘
```

맨 위에 **세 개의 `main`** 비교판이 항상 떠 있습니다 — 내 `main` / `origin/main` 메모 / GitHub의 `main`.
셋이 어긋나는 방식마다 배울 것이 달라서 안내 문구가 네 갈래로 갈립니다.

`git pull`은 **fetch와 merge 두 장면으로 나눠** 보여줍니다. 하나로 묶으면 "pull = 다운로드" 오해가 그대로 남습니다.

### 지원 명령 20종

```text
git init · status · log · diff [--staged]
git add · commit [-m|--amend --no-edit] · restore [--staged]
git branch [-d|-a] · switch [-c]
git remote add|-v · fetch · push [-u] · pull [--ff-only] · merge [--abort]
git reset [--soft|--mixed|--hard] · revert
git stash [push|list|apply|pop|drop] [-u]
git rebase <upstream> [--continue|--skip|--abort]
git worktree [list|add [-b]|remove [--force]]
```

파서는 **허용 목록**입니다. 모르는 명령은 조용히 무시하지 않고 이유를 말합니다 —
그러지 않으면 사용자는 자기가 오타를 냈는지 실습실이 모르는 것인지 구분할 수 없습니다.
`checkout`을 치면 `switch`/`restore`로 안내하고, `cherry-pick`·`reflog`·`clone`·`config`는
다루지 않는다고 답합니다.

### 충돌은 실패가 아닙니다

초보자가 Git에서 가장 무서워하는 장면인데, 대표 시나리오가 지금까지 **일부러 이걸 피해**
서로 다른 파일을 건드리도록 만들어져 있었습니다. 지금은 정면으로 다룹니다.

```text
merge → 마커가 든 파일 → 사람이 고름 → git add(=정했다) → git commit(부모 둘)
```

- 파일 비교는 **줄 단위**입니다. 같은 파일이라도 **서로 다른 줄**을 고쳤으면 알아서 합쳐집니다.
  "왜 어떤 건 알아서 되고 어떤 건 안 되나"를 이해하는 자리가 정확히 여기입니다
- 충돌하면 거절하지 않고 `<<<<<<< HEAD` 마커가 든 파일을 **작업 폴더에 실제로 써두고** 멈춥니다.
  화면에서도 빨강이 아니라 노랑입니다 — 빨강으로 칠하면 뭔가 잘못했다고 읽힙니다
- **충돌 중의 `git add`는 뜻이 하나 더 있습니다** — "이 파일은 내가 정했다"는 선언입니다.
  같은 명령에 두 뜻이 겹치는 자리라 말로 설명합니다
- **마커를 그대로 둔 채 `add`해도 막지 않습니다.** 실제 Git도 확인해주지 않습니다.
  대신 크게 경고합니다 — 막아버리면 진짜 터미널에서 물릴 때 대비가 안 됩니다
- 충돌 파일은 `status`에서 **Unmerged paths로 따로** 보여줍니다. 스테이징에 섞으면
  화면이 "커밋할 준비가 됐다"고 거짓말을 합니다

마커를 걷어내는 것은 Git 명령이 아니라 편집기로 하는 일이라, 화면 버튼(내 것/저쪽 것/둘 다)이
파일을 고치고 끝냅니다. 그래서 `git add`가 **왜 따로 필요한지**가 저절로 드러납니다.

### `stash` · `rebase` · `worktree`

셋 다 Git의 핵심 개념인데 실습이 없으면 설명만으로는 잘 안 붙습니다.

| 명령 | 이 실습실이 보여주려는 한 가지 |
|---|---|
| `stash` | 커밋하기 애매한 작업을 **치웠다 꺼내기**. `-u` 없이는 한 번도 `add`한 적 없는 파일이 안 치워집니다 |
| `rebase` | 커밋을 옮기는 게 아니라 **다시 적는 것**. 그래서 id가 바뀌고, push가 거절되고, `--force`가 위험해집니다 |
| `worktree` | 기록함은 하나인데 **작업 폴더는 여러 개**. `stash`가 "치웠다 꺼내기"라면 이건 "동시에 열어두기"입니다 |

`stash`를 넣은 직접적인 이유는 따로 있습니다. 실습실은 `switch`가 거절될 때
"먼저 커밋하거나 치워두세요"라고 안내해 왔는데, **치워둘 방법을 주지 않고 있었습니다.**
테스트가 그 길이 실제로 통하는지 확인합니다 — 거절 → `stash` → `switch` 성공.

`rebase`는 README가 오래 "숙련자용, 범위 밖"으로 두던 명령입니다. 넣기로 한 것은
명령을 하나 더 가르치기 위해서가 아니라 이 연쇄를 **직접 보여줄 수 있기 때문**입니다 —
기록을 다시 쓰면 → id가 바뀌고 → push가 거절되고 → 그때 `--force`로 밀면
동료가 받아간 커밋이 사라집니다. 엔진 구조상 이게 저절로 참이 되고, 테스트가 통째로 확인합니다.

`worktree`의 안전장치는 **같은 작업본을 두 폴더에서 열 수 없다**는 것입니다.
두 군데서 열면 한쪽에서 커밋할 때 다른 쪽 작업 폴더가 조용히 어긋나기 때문입니다.
폴더를 오가는 것은 Git 명령이 아니라 `cd`라서, 터미널이 아니라 **탭**으로 뒀습니다.

### 명령을 고르는 방법 — 버튼 대신 자동 완성

입력창 아래에 목록이 뜹니다. 버튼을 늘어놓지 않은 이유가 셋입니다.

1. 명령을 **치는 곳과 고르는 곳이 같아야** 눈이 움직이지 않습니다
2. **지금 저장소에 있는 실제 이름을 채워 넣을 수 있습니다** —
   `git add <파일>`이 아니라 `git add 설정.txt`가 바로 나옵니다
3. 목록이 길어져도 화면을 잡아먹지 않습니다

각 항목에는 명령과 함께 **어느 칸이 바뀌는지**가 적혀 있습니다. 고르는 동안에도 그것을 읽게 됩니다.
`reset --hard`처럼 되돌릴 수 없는 것에는 ▲ 위험 표시가 붙습니다.

WAI-ARIA combobox 패턴을 따릅니다. **초점은 입력창에서 나가지 않고**, 지금 고른 항목은
`aria-activedescendant`로만 알립니다. 그리고 **목록을 열자마자 첫 항목을 고르지 않습니다** —
그러면 직접 친 명령을 <kbd>Enter</kbd>로 실행하려던 사람이 엉뚱한 제안을 실행하게 됩니다.
고르려면 <kbd>↓</kbd>를 눌러야 합니다.

### 시나리오 10종과 "힌트가 진짜 맞는가"

시작 상태를 **손으로 적지 않습니다.** 전부 엔진에 실제 명령을 실행시켜 만듭니다.
손으로 적은 상태 하나가 틀리면 사용자는 그것을 자기 저장소로 오해합니다.

각 시나리오에는 목표와 힌트 순서가 붙어 있고, **테스트가 그 힌트를 그대로 쳐서 목표에 닿는지 확인합니다.**

```bash
node --test tests/*.test.js     # 83개
```

> 틀린 힌트는 틀린 설명보다 나쁩니다. 사용자는 그대로 따라 치고, 안 되면 자기가 잘못 쳤다고 생각합니다.

### AI 결과 → 같은 상황 재현

결과 카드(그리고 정적 카드 8종)에 **"실습실에서 재현하기"** 버튼이 붙습니다.

**서버와 프롬프트는 건드리지 않았습니다.** AI 응답에 재현용 필드를 새로 만드는 대신,
이미 있는 `그래프템플릿`을 시나리오 id로 매핑합니다(`js/sim/scenario-map.js`).
그 값은 상황을 이미 식별하고, `api/rescue.py`와 화면 양쪽에서 이미 허용 목록 검증을 통과합니다.
새 필드를 만들면 AI가 채우는 값이 하나 늘고 검증할 표면도 하나 늡니다.

- 정적 카드 8종 중 7종에 붙습니다. `그래프템플릿: none`인 하나에는 붙지 않습니다
- **대응하는 시나리오가 없으면 붙이지 않습니다.** 억지로 비슷한 상태를 만들어 열면
  사용자는 그것을 자기 저장소로 오해합니다 — 그래프를 억지로 그리지 않는 것과 같은 이유입니다(§9)
- `lab.html?scenario=…`의 값은 믿지 않습니다. 목록에 없으면 기본 시나리오로 엽니다

### 실습실이 지키는 것

| 무엇을 | 어떻게 |
|---|---|
| 실제 파일 | 읽지도 바꾸지도 않습니다. 네트워크로 나가지 않아 정적 서버만으로 전부 동작합니다 |
| 안 바뀐 칸 | 바뀐 칸과 **함께** 보여줍니다. 둘을 손으로 적지 않고 5칸에서 빼서 만듭니다 |
| XSS | 엔진에서 온 값은 전부 `escapeHtml`. 강조(`**`)는 **이스케이프한 뒤에** 태그로 바꿉니다 |
| CSP | 인라인 `style=`도 인라인 `<script>`도 없습니다 (§8의 `style-src 'self'`) |
| 그림 정직성 | 이 화면 그래프는 개념 예시가 아니라 실습실 안의 실제 상태라고 적습니다(§11) |
