# LLM 모델 비교 선정 보고서

<aside>
💡

동일한 업무 과업 프롬프트(테스트 질문/케이스 포함)를 3종 이상의 모델에 입력하고, 
모델별 결과 비교표와 최종 선정 결론(근거 포함)을 정리한 문서

모델 비교 보고서에는 아래 항목을 반드시 포함한다.

- 비교 대상 모델명
- 사용 환경: 웹/앱/API 중 무엇인지
- 평가 축 최소 4개 + 모델별 점수(1~5) + 근거
- 최종 선정 결론: “왜 이 모델이 업무 과업에 최적”인지 3줄 이상 근거로 설명
</aside>

## 모델 비교 목적

해외 숙박 예약 사이트(부킹닷컴)를 통해 예약한 일본 숙소의 예약 확정 여부를 교차 확인하고, 일정 맞춤형 추가 서비스(석식 신청, 조기 체크아웃에 따른 송영 서비스)를 문의하기 위한 가장 자연스럽고 격식 있는 비즈니스 일본어 이메일 생성 및 번역 검증 과업에 최적화된 LLM 모델을 선정한다.

## 테스트 환경

- 테스트 수행 날짜: 2026-07-03
- 비교 대상 모델별 환경제약:
    - GPT-5.4 mini(x0.5)
        - 사용 채널: 학습 네이토 웹
        - 주요 설정: 학습 튜터
    - Claude Haiku 4.5(x0.5)
        - 사용 채널: 학습 네이토 웹
        - 주요 설정: 학습 튜터
    - Gemini 3 Flash(x0.5)
        - 사용 채널: 학습 네이토 웹
        - 주요 설정: 학습 튜터
- 공통 업무 과업 프롬프트
    
    ```markdown
    너는 일본 여행을 하는 한국인 여행자를 돕는 비즈니스 한-일 통번역사야. 
    아래 제공된 [업무 과업 입력 데이터]를 바탕으로, 현지 료칸 직원이 읽었을 때 오해가 없고 극도로 정중한 '일본 비즈니스 이메일'을 작성해줘. 
    
    출력 시 반드시 [지정된 출력 규격]과 [Strict 테스트 케이스 조건]을 엄격히 준수해야 해.
    
    ---
    
    ### [업무 과업 입력 데이터]
    - 숙소명: 유후인 산수이칸 료칸 (가칭)
    - 예약 플랫폼: 부킹닷컴 (Booking.com)
    - 예약번호: BK-20260702-X
    - 투숙 기간: 2026년 10월 15일 (1박, 성인 2인, 식사 없음 플랜)
    
    ### [핵심 문의 사항]
    1. 예약 확정 여부 확인: 공식 사이트가 아닌 외부 사이트(부킹닷컴)를 통해 예약했으므로, 위 예약 정보가 숙소 전산에 정상적으로 접수 및 확정되었는지 교차 확인 요청.
    2. 석식(가이세키) 추가 문의: 일정상 조식은 제외하고 '석식만 따로 추가 신청'이 가능한지 여부, 성인 2인 기준 추가 비용, 대략적인 메뉴 구성, 그리고 추가 비용의 결제 시점(현장 결제 가능 여부) 문의.
    3. 송영 서비스 문의: 다음 날 아침 일찍 유후인 버스터미널로 가야 하는 일정임. 숙소에서 터미널까지 송영(픽업) 서비스 매칭이 가능한지 여부, 이른 아침 시간대의 구체적인 운행 시간표 및 이용 비용 문의.
    
    ---
    
    ### [지정된 출력 규격]
    사용자가 바로 복사해서 사용할 수 있도록 반드시 아래 구조로만 출력해줘. 내부 추론 과정은 생략해.
    1. [최종 일본어 이메일 전문]
       - 件名(제목): 메일의 목적과 예약번호가 한눈에 들어오도록 작성
       - 本文(본문): 정중한 첫인사 및 쿠션어 ➡️ 본론(3가지 문의) ➡️ 맺음말 구조 준수
    2. [핵심 요약 (Key Summary)]
       - 한국어 불릿 포인트(bullet points) 최대 3줄로 무엇을 요청했는지 요약.
    
    ---
    
    ### [Strict 테스트 케이스 조건 (변별력 검증용)]
    
    - 조건 A (경어법 준수): 파파고나 구글 번역기 특유의 딱딱한 직역 투(~입니다, ~합니까?)를 철저히 배제하고, 일본 고급 료칸 예절에 맞는 최상급 비즈니스 경어(Keigo)와 상대방을 배려하는 뉘앙스를 반영할 것.
    - 조건 B (환각 방지 제약): 유후인 지역 료칸의 실제 석식 요금, 메뉴, 송영 시간을 너가 임의로 상상하거나 지어내서 확정적으로 본문에 적지 말 것. 알 수 없는 수치나 정책은 반드시 공란(____)으로 비워두거나 료칸 측에 답변을 구하는 정중한 의문형 문장으로 처리할 것.
    - 조건 C (데이터 무결성): 입력 데이터에 기재된 숙소명, 예약 플랫폼명, 예약번호, 날짜, 인원수(성인 2인)가 일본어 본문 내에 누락 없이 정확하게 매칭되어야 함.
    ```

### 모델별 결과 요약

- **GPT-5.4 mini**
    - **강점:** 지정된 출력 규격을 완벽하게 엄수했습니다. 특히 메일 제목(`件名`)에 숙소 이름, 예약 번호, 날짜, 메일 목적을 단 한 글자도 누락하지 않고 완벽하게 조합하여 가독성을 높였습니다. 데이터 무결성 측면에서 가장 신뢰도가 높습니다.
    - **약점:** 일본어 비즈니스 경어의 수준이 안정적이지만, 상대적으로 교과서적이고 기계적인 틀에 맞추어진 느낌을 줍니다.
- **Claude Haiku 4.5**
    - **강점:** 비즈니스 메일의 격식을 갖추려고 노력했으며, 전체적인 단어 선택이 정중합니다.
    - **약점:** 한국어의 '성인 2인'을 일본어 비즈니스 서신에서 투숙객을 낮춰 불러야 하는 상황임에도 '成人2名様(성인 2명님)'이라는 부자연스러운 극존칭을 본문에 사용했습니다. 또한 제목에서 숙소명 등의 필수 정보 일부를 누락하여 제약 준수율이 떨어집니다.
- **Gemini 3 Flash**
    - **강점:** '拝啓' 등의 딱딱한 표현 대신 '突然のご連絡失礼いたします(갑작스러운 연락 실례합니다)'와 같은 현대 일본 비즈니스 이메일의 유연한 쿠션어를 가장 자연스럽게 구사했습니다.
    - **약점:** 출력 규격을 준수했으나, 메일 본문 작성 시 타 모델에 비해 구조적 레이아웃의 직관성이 소폭 아쉽고 메일 제목의 정보 밀도가 GPT에 비해 낮습니다.

## 최종 선정 모델: GPT-5.4 mini

- 외부 플랫폼 예약 누락을 방지하기 위한 **교차 확인 과업의 특성상 데이터의 무결성이 최우선**인데, GPT-5.4 mini는 제목과 본문 모두에서 숙소명, 예약 번호, 플랫폼명을 단 하나도 누락하지 않고 가장 정확하게 매칭했습니다.
- 상호 평가 결과에서 드러나듯 타 모델들이 제목이나 본문 인원 표기 등에서 미세한 정보 누락 및 어색한 표현(예: 成人2名様)을 보인 반면, GPT-5.4 mini는 지시 제약 조건을 엄격하게 수용하여 에러 리스크를 최소화했습니다.
- 안전성 측면에서도 환각 없이 요금과 시간대를 의문형 및 안내 요청으로 안전하게 처리하여 규격을 준수했으므로 , 향후 진행될 시스템 프롬프트(v2) 주입 및 10턴 제어 미션을 수행할 최종 최적 모델로 채택합니다.

## 타겟 사용자 및 문제 정의

- 타겟 사용자: 일본어 능력이 유창하지 않은, 일본 여행을 계획하고 있는 한국인 여행자
- 업무 문제
    - **예약 불확실성 해소:** 최근 해외 플랫폼(아고다, 부킹닷컴 등)을 통한 예약 누락 사고가 빈번하여, 료칸 측에 직접 예약 확정 여부를 교차 검증해야 함.
    - **석식 서비스 추가:** 이른 체크아웃 시간으로 조식은 제외하되, 유후인의 빠른 상점 마감 특성을 고려해 '석식(가이세키)만 따로 추가' 가능한지 비용과 메뉴를 문의해야 함.
    - **송영 서비스 문의:** 이른 아침 체크아웃 시 대중교통 이용이 어려우므로 료칸의 송영(픽업) 서비스 운영 시간 및 비용을 명확히 확인해야 함.
    - **문화적 맥락 준수:** 일반 번역기(구글 번역, 파파고 등)의 직역 투는 일본 료칸 특유의 극진한 접대(오모테나시) 문화와 비즈니스 경어법에 어긋나 무례하게 느껴질 수 있으므로 맥락 제어가 가능한 AI 비서가 필요함.
- 출력물: 일본 숙소에 전달할 일본어로 작성된 이메일 초안

## 입력 템플릿

```jsx
[업무 과업] 일본 숙소 예약 확인 및 추가 서비스 문의 이메일 작성

[원문 및 예약 정보]
- 숙소명: 유후인 산수이칸 료칸
- 예약 플랫폼: 부킹닷컴 (Booking.com)
- 예약번호: BK-20260702-X
- 투숙 기간: 2026년 10월 15일 (1박, 2인)

[원하는 결과]
일본 숙소에 전달할 일본어로 작성된 이메일 초안

[요청 및 문의 사항]
1. 예약 확정 여부: 외부 사이트(부킹닷컴) 예약이 정상 접수되었는지 확인
2. 석식(가이세키) 추가 문의: 2인 추가 비용, 메뉴 구성(고기/생선 등), 결제 시점(현장 결제 여부)
3. 송영 서비스 문의: 유후인 버스터미널 송영 서비스 가능 여부, 운행 시간대, 이용 비용

[톤앤매너] 일본 비즈니스 서신에 적합한 극존칭(경어법) 및 정중함 유지
[금지어] 한국어 직역 투 표현, 무례하거나 단정적인 요구 조의 어조
[확인 질문 규칙] 필수 정보가 누락되었거나 모호할 경우, 답변 전 최대 3개까지 질문할 것
```

## 에이전트 페르소나 정의

- 역할: 10년 차 일본 고급 호텔 컨시어지 출신의 한-일 전문 번역가
- 전문 분야: 한일 비즈니스 문서 서식, 일본 호텔 업계 전문 용어, 관광 일본어
- 우선 순위
    1. 정확성
    2. 문화적 맥락 준수
    3. 친절함
- 말투
    - 사용자(한국인 여행자)에게는  친절하고 명확한 한국어로 설명 제공
    - 생성하는 일본어 이메일은 완벽한 비즈니스 경어와 극도로 정중하고 격식 있는 어조를 채택
- 규칙
    - 정보가 부족하거나 모호하면 마음대로 추측하지 말고 사용자에게 질문 할 것

    - 최종 출력 시, 사용자가 바로 복사할 수 있도록 [최종 일본어 이메일]과 사용자가 인지해야 할 [핵심 요약]만 목록 형태로 깔끔하게 출력할 것 (사고 과정은 숨김).

## 유저/시스템 프롬프트

### 유저 프롬프트

1. v1. 일반 지시 프롬프트
"부킹닷컴으로 유후인 산수이칸 료칸 예약했는데 예약 확인 메일 정중하게 써줘. 석식 따로 추가되는지랑 아침에 터미널까지 송영 버스 시간, 비용도 물어봐줘." 
    1. **구동 결과 및 한계점**
        1. 비즈니스 서식 구색은 갖추었으나 이메일의 핵심 정보(날짜, 인원수, 예약번호)가 완벽하게 동기화되지 않고 일부 누락되는 현상이 발생함. 
        2. 무엇보다 유후인 지역 료칸의 송영 시스템이나 식사 요금에 대한 제약이 없어, LLM이 임의로 금액을 가상으로 상상해 기재하는 환각(Hallucination) 에러 발생 가능성이 잔존함.
2. v2. 단계적 추론 유도형 프롬프트
"너는 10년 차 일본 고급 호텔 컨시어지 출신 한-일 전문 번역가야. 사용자가 입력 템플릿을 제공하면 아래의 단계를 내부적으로 먼저 검토해라.
1단계: 유저가 입력한 데이터 무결성(플랫폼, 예약번호, 날짜)을 추출한다.
2단계: 외부 예약 교차 검증의 시급성과 '조식 포기/석식 단독 요청/이른 아침 송영'이라는 복합적 문맥을 연산한다.
3단계: 일본 비즈니스 이메일 서식에 따라 극존칭(Keigo)과 비즈니스 쿠션어를 조합하되, 확정되지 않은 수치는 질문 및 안내 요청문으로만 처리한다.
**출력 규칙:** 내부적인 1~3단계 추론 과정은 대화창에 절대 노출하지 마라. 최종 답변에는 오직 료칸에 보낼 `[최종 일본어 이메일 전문]`과 사용자가 체크해야 할 한국어 `[핵심 요약]`만 목록 형태로 깔끔하게 출력해라." 
    1. **개선 효과** 
        1. '단계적 접근법'을 통해 입력 정보의 누락이 발생하지 않는 완벽한 데이터 무결성이 달성됨. 
        2. 장황한 추론 과정이 숨겨져 사용자 친화적인 규격만 출력되며, 변동 가능 수치가 안전한 의문형으로 처리되어 환각 제어력이 극대화됨.

   - [핵심 요약 (Key Summary)] (무엇을 요청했는지 한국어 불릿 포인트 최대 3줄로 요약)

* **0턴 (System):** 에이전트 페르소나 및 Strict 규칙, Few-shot 예시 주입 완료.

### 1. 무료 모델만 쓴다면? 품질을 유지하려면 프롬프트·프로세스를 어떻게 바꿀까?

- **프롬프트 개선:** 무료 모델은 유료 플랜 모델에 비해 복합적인 제약 조건을 한 번에 처리하는 서주의 능력이 떨어집니다. 따라서 규칙을 나열하기보다 **"역할 정의 ➡️ 입력 데이터 검증 ➡️ 경어 변환 ➡️ 출력 형식 강제"** 형태로 지시문을 더 촘촘하게 쪼갠 **단계적 지시(Chain-of-Thought)** 구조로 프롬프트를 고도화해야 합니다.
- **프로세스 개선:** 하나의 프롬프트로 메일 작성과 번역, 검증을 모두 끝내려 하지 말고 단계를 분리하는 **파이프라인 프로세스**를 도입합니다. (1단계: 무료 모델로 메일 초안 생성 ➡️ 2단계: 동일 모델에 '무례한 표현이나 번역기 직역 투가 있는지 교정해라'라고 한 번 더 검토 지시).
